# 6. User Stories & Acceptance Criteria

## US-01
**Как клиент банка, я хочу создать заявку на брокерский счёт, чтобы начать процесс дистанционно.**

### Acceptance Criteria
- Given клиент авторизован,
- When нажимает «Открыть брокерский счёт»,
- Then создаётся заявка со статусом `DRAFT`,
- And клиент получает `applicationId`.

## US-02
**Как клиент, я хочу видеть статус заявки, чтобы понимать, что происходит.**

### Acceptance Criteria
- Статус отображается в приложении.
- Показывается дата последнего изменения.
- Для каждого статуса есть человекочитаемое описание.

## US-03
**Как клиент, я хочу получить понятную ошибку, если заявку нельзя отправить.**

### Acceptance Criteria
- Ошибка содержит `code`.
- Пользователь видит понятное `message`.
- Технические детали не выводятся пользователю.

## US-04
**Как сотрудник продукта, я хочу видеть историю статусов, чтобы расследовать спорные случаи.**

### Acceptance Criteria
- Каждое изменение содержит old_status, new_status, changed_at.
- История не перезаписывается.

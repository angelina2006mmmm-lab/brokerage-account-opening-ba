# 5. Use Cases

## UC-01 — Создание заявки

**Actor:** Клиент  
**Preconditions:** клиент авторизован, профиль активен.  
**Trigger:** клиент выбирает «Открыть брокерский счёт».

### Main Flow
1. Система проверяет доступность продукта.
2. Система создаёт заявку в `DRAFT`.
3. Система возвращает `applicationId`.
4. Пользователь переходит к заполнению/проверке данных.

### Alternative Flow
- A1: уже существует активная заявка → система возвращает её идентификатор.
- A2: продукт недоступен → система возвращает бизнес-ошибку.

---

## UC-02 — Отправка заявки

**Preconditions:** есть `DRAFT`, обязательные данные и согласия заполнены.

### Main Flow
1. Клиент нажимает «Отправить».
2. Система валидирует данные.
3. Заявка меняет статус на `SUBMITTED`.
4. Запускаются проверки.
5. Заявка переводится в `UNDER_REVIEW`.

### Exceptions
- Нет обязательного согласия → `CONSENT_REQUIRED`.
- Не заполнено обязательное поле → `VALIDATION_ERROR`.

---

## UC-03 — Получение статуса

1. Клиент открывает экран заявки.
2. Приложение запрашивает статус.
3. API возвращает статус, дату изменения и пользовательское описание.

---

## UC-04 — Запрос дополнительной информации

1. Проверка выявляет недостаток данных.
2. Статус → `ADDITIONAL_INFO_REQUIRED`.
3. Клиент видит список необходимых действий.
4. После исправления заявка повторно отправляется на проверку.

---

## UC-05 — Открытие брокерского счёта

1. Проверки успешно завершены.
2. Статус заявки → `APPROVED`.
3. Система создаёт брокерский счёт.
4. Заявка → `ACCOUNT_OPENED`.
5. Клиент видит номер счёта и следующий доступный шаг.

# 8. Acceptance Test Plan

## Цель
Проверить, что реализованный процесс соответствует бизнес- и функциональным требованиям.

## Критические пользовательские сценарии
1. Успешное открытие счёта.
2. Попытка отправить заявку без согласий.
3. Повторное создание активной заявки.
4. Недостаточные персональные данные.
5. Переход в `ADDITIONAL_INFO_REQUIRED`.
6. Отказ по результатам проверки.
7. Получение актуального статуса.
8. Проверка истории статусов.

## Exit Criteria
- Все Critical/High тесты пройдены.
- Нет открытых Critical/Blocker дефектов.
- Бизнес-переходы статусов соответствуют модели.
- API-контракты соответствуют OpenAPI.
- Пользовательские тексты согласованы.

# 3. Functional Requirements

## FR-01. Запуск процесса
Система должна отображать пользователю действие «Открыть брокерский счёт».

## FR-02. Проверка доступности
Перед началом процесса система должна проверить:
- пользователь авторизован;
- профиль пользователя активен;
- обязательные идентификационные данные заполнены.

## FR-03. Черновик заявки
Система должна позволять создать заявку в статусе `DRAFT`.

## FR-04. Согласия
До отправки заявки система должна получить обязательные согласия пользователя.

## FR-05. Отправка
Пользователь должен иметь возможность отправить заполненную заявку.

## FR-06. Валидация
При отправке система должна проверить обязательные поля и согласия.

## FR-07. Обработка
После отправки статус должен измениться на `SUBMITTED`, затем на `UNDER_REVIEW`.

## FR-08. Дополнительная информация
Если данных недостаточно, система должна перевести заявку в `ADDITIONAL_INFO_REQUIRED`.

## FR-09. Одобрение
После успешной проверки заявка переводится в `APPROVED`.

## FR-10. Создание счёта
После одобрения система должна создать брокерский счёт и перевести заявку в `ACCOUNT_OPENED`.

## FR-11. Отказ
При отрицательном результате заявка переводится в `REJECTED`.

## FR-12. Статус
Пользователь должен иметь возможность получить актуальный статус заявки.

## FR-13. История
Каждое изменение статуса должно записываться в историю.

## FR-14. Защита от дублей
Для одного клиента не должно быть более одной активной заявки одного типа одновременно.

## FR-15. Ошибки
API должен возвращать структурированную ошибку с машинным `code` и пользовательским `message`.
